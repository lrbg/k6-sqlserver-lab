Paso a paso del pipeline
1

Trigger

Arranca por cron diario o de forma manual con Run workflow (inputs: escenario, VUs, duracion).

2

Construir k6

xk6 compila un k6 con xk6-sql + driver de SQL Server. El binario se cachea entre corridas.

3

Levantar SQL Server

docker run de mssql/server:2022. La base vive solo durante la corrida.

4

Esperar readiness

Reintentos con sqlcmd hasta que el motor responde SELECT 1.

5

Sembrar datos

seed.sql crea el esquema de ventas y carga 5k clientes / 20k ordenes / 60k renglones con GENERATE_SERIES.

6

Ejecutar k6

Workload OLTP (5 tipos de query). Mide p50/p95/p99, throughput y % de error por query.

7

Validar con agente IA

El agente (GitHub Models) analiza las metricas. El veredicto PASS/WARN/FAIL se calcula aparte de forma determinista vs los SLOs.

8

Reportar

Markdown con graficas Mermaid, se commitea, actualiza el README y sube los artefactos.

Como se divide la arquitectura
Capa 1
Orquestacion

GitHub Actions

Dispara (cron + manual), controla permisos (contents:write, models:read) y encadena los pasos.

▼
Capa 2
Carga

k6 + xk6-sql

Motor que genera la carga: usuarios virtuales, thresholds y metricas por tipo de query.

▼
Capa 3
SUT

SQL Server 2022 (contenedor)

Sistema bajo prueba, auto-contenido y sembrado. Sin base de datos externa ni secrets.

▼
Capa 4
Validacion

Agente IA + veredicto

Analisis en lenguaje natural (cuello de botella, indices) y badge determinista por SLO.

▼
Capa 5
Publicacion

Reporte + evidencia

metrics.json → gen_report.py → Markdown + Mermaid, commit al README y artefactos.
